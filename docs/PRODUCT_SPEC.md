# Product Spec — Royal Keys Brokerage OS

## Business model

- **Sale:** 3% of the final successful transaction value.
- **Rental placement:** 50% of one month's agreed rent on successful tenant placement.
- No core success fee merely for a listing submission.
- Final client obligations must be defined in signed agency terms.

## Primary public journeys

### Buyer
Search → property → qualify → introduction record → viewing → offer → negotiation → sale → 3% commission.

### Tenant
Search → property → qualify → introduction record → viewing → rental application → lease → half-month placement commission.

### Seller
Submit owner/property → review → agency terms → marketing → qualified leads → viewings → offers → deal → commission.

### Landlord
Submit owner/property → review → agency terms → tenant acquisition → viewings → applications → placement → commission.

## Brokerage dashboard

- Inventory and owner review.
- Lead scoring and source visibility.
- Match Center.
- Introduction attribution.
- Viewing calendar/list.
- Offer and rental application queues.
- Deal close action.
- Commission generation and payment status.
- Follow-up queue.

## Lead score

Operational prioritization only. Inputs:

- purchase/move timeline;
- verified contact;
- viewing readiness;
- budget match.

The score must not be presented as financial, credit, legal or eligibility advice.

## Matching

The current deterministic matching uses:

- transaction type;
- city/area;
- property type;
- budget;
- bedroom requirement.

The score is explainable and should remain visible to staff. AI can assist later, but must not replace the deterministic criteria without clear reasoning and tests.

## Commission attribution

Every meaningful property enquiry should create an Introduction record before contact/viewing details are exchanged. The protection period is a contractual concept and must be configured to match signed legal terms.
